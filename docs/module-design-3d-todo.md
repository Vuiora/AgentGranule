# 模块分析、3D 展示与人工设计力度：实施状态

用户已要求实现本文件的三个阶段，现已在 `codex/module-design-3d` 完成代码、Skill 与测试。Python 框架支持静态源码分析，任意任务的语义模块分解由 Skill 宿主依据实际材料完成；原生 3D 模块视图及完整力度清单的人工确认已实现。下方勾选表示功能已实施与程序验收，不代表真实调用者已经批准任何任务设置或 Git PR。

目标流程是：宿主 Agent 分析框架与任务，提出模块及依赖 → 展示可供检查的 3D 模块图 → Skill 调用者逐模块手动分配设计力度并明确确认 → 保存设置、刷新视图和调度受影响任务。

## 2. 设计力度的数据约定

`design_effort` 表示人工希望某模块在某个处理方向投入的相对设计力度，沿用 `(module, direction, parameters)` 的领域结构。它与 `detail_level`、整数 `count`、整数 `max_depth` 可并存；小数要求只应用于声明支持小数的选项。

调用者已选择 `0.00–1.00`、步长 `0.01` 作为本轮 `design_effort` 的固定尺度。它表示相对力度，不直接承诺固定令牌、用时或内容质量，也不自动把 0.50 翻译为某个列举数目。宿主须在实际任务中说明该参数如何影响处理。JSON 数值可能显示为 `0.5`；界面显示 `0.50`，二者表示同一值，不以字符串尾零判断精度。

后续可选扩展（不改变本轮已确认的固定尺度）：为确有不同尺度的选项建立可配置的参数定义，显式声明字段、最小值、最大值、步长和解释；不能只放大滑块范围而不更新后端校验与宿主契约。范围变更须保留旧设置的尺度与历史版本，避免将原来的 0.50 悄然解释成另一种力度。

人工分配默认是各模块独立设值，不隐含“总和必须为 1”的预算约束。如果需要总量预算，须增加明确的预算模式与单独校验，不能静默归一化调用者的选择。`0.00` 保留为有效设置；它的任务执行含义需由宿主说明，不自动删除模块、跳过任务或批准未执行的结果。

## 3. 分阶段 TODO 与验收

### 阶段 A：分析框架并形成任务模块清单

- [x] Skill 先读取实际需求与材料，提出模块清单：稳定 ID、名称、职责、预期输出、处理方向、可选父模块、依赖、分解依据和需要调用者补充的内容。
- [x] 区分结构嵌套关系与执行依赖，分别呈现；用现有 DAG 校验拒绝重复 ID、未知依赖、循环与跨会话关联。
- [x] 在创建执行工作流前让调用者检查分解，可修改模块与依赖；Agent 提出的分解不等同于人工力度设置。
- [x] 人工接受后保存分析原文及模块清单版本。后续改动清单或材料时创建新工作流，保留旧图与旧结果，不改写现有固定任务图。

验收：给出有材料依据、可由人逐项修改的模块清单；独立模块、嵌套模块和任务依赖均能表达；错误图无法进入执行；原始分析与修改仍可追溯。

### 阶段 B：在原生宿主中展示 3D 模块图

- [x] 建立只读取统一状态的视图模型：模块 ID、名称、父关系、依赖边、当前方向、力度值、设置来源、修订和任务状态。
- [x] 对同一模块的多个方向提供明确切换，尺寸反映当前选定方向；若以后需要综合尺寸，先定义并显示聚合规则，不悄然取平均或最大值作为“模块总力度”。
- [x] 在同一张图中为全部模块使用半透明倒角薄片与可复现布局，共享 3D 相机；明确区分父子关系与依赖边；支持旋转、缩放、片区／标签选择、组内重叠点选菜单和文字详情。仅按已有父／依赖关系成组，为无关联组预留最大力度空间，力度变化不移动其他组，旋转后仍分离。片区重叠不推断职能交集；不使用球体。
- [x] 按力度改变**几何体体积**。设 `e∈[0,1]`，用 `V(e)=Vmin+(Vmax−Vmin)×e`；薄片采用固定厚度，平面面积线性变化、平面尺寸按平方根变化，`Vmin>0` 让零力度模块仍可见。
- [x] 展示数值与图例，明确尺寸表示人工设置的力度，不能解释为完成质量、实际资源消耗或模块的重要性。未分配力度显示“待分配”及固定占位尺寸，不伪造人工选择。
- [x] 拖动分配控件时即时更新预览；确认后切换为已保存状态；取消时恢复保存值。其他入口的变更须触发刷新或明确显示冲突。
- [x] 在实现阶段选择与本地宿主兼容的 3D 渲染方案，验证目标系统的依赖、渲染性能与文字可读性。入口保持原生宿主形式，不恢复已被否决的独立网页方案。

验收：0.00、0.01、0.50、1.00 的尺寸单调且符合声明的体积映射；零值可见、未设置可辨；缩放与透视不遮蔽数值读取；图与数据库修订一致；只能预览的变化不写入设置。

### 阶段 C：由 Skill 调用者手动分配设计力度

- [x] Skill 在已确认模块图基础上，由本地宿主打开力度分配窗口；MCP 负责状态操作，宿主负责真实界面及实际人工回答。
- [x] 分配窗口逐模块呈现名称、方向、当前来源和修订；允许滑动及精确输入 0.01 的值，只修改本次选定的字段，保留同一参数对象中的其他设置。
- [x] 在正式提交前展示分配清单与受影响任务，调用者可返回修改；默认值和 Agent 建议明确标注来源，不自动记为人工批准。
- [x] 提交时比较每项快照的有效参数、来源、修订和模块图版本。任一项过期时拒绝整次批量提交，让调用者重新加载和确认；通过时在一个事务中保存全部设置与对应事件。
- [x] 取消、关窗、弹窗启动失败或结果文件缺失均不写入批准；保存结果须与数据库实际状态及当前目标模块／方向相符。
- [x] 保存真实的用户／助手可见交互和每项力度变更，包括原值、新值、来源、修订与确认结果；研发阶段继续手工记录对话。只记录宿主显式回传内容，不自动读取其他聊天。
- [x] 保存后刷新现有工作流：发生力度变化的任务及其依赖后继重算，无关分支保留有效结果；旧请求不能提交到新修订。

验收：调用者完成一次真实手动分配后能够继续任务；非法小数、越界、过期快照和并发冲突有明确反馈；批量提交全成或全败；取消不改变设置；重启后保留已确认力度与记录；局部重算保留无关模块结果。

## 4. 下一阶段实现边界
