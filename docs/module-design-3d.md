# 模块分析、原生 3D 与人工设计力度

完整流程：分析实际材料形成模块提案 → 调用者检查并确认模块清单 → 3D 显示模块及关系 → 调用者为各模块／方向分配设计力度 → 原子确认整份清单 → 领取并执行任务。

## 分析入口

`analyze_framework(root_path)` 静态读取 Python 框架，优先使用项目的 src 目录，分析模块说明、公开类／函数和本地导入关系；不导入、不执行被扫描代码。返回 `analysis` 提案、来源目录与模块数。导入依赖是待审阅的建议，结构嵌套与执行依赖分别表达。若源码导入存在循环，返回完整 import_relationships 及警告，提案中的执行依赖暂为空，须由宿主与调用者调整。

任意任务的语义分解仍由 Skill 宿主依据实际需求与材料完成，框架不接模型供应商，也不把 Python 文件结构强加给其他任务。提案的每个模块包含稳定逻辑 ID、名称、职责、预期输出、分解依据、方向列表、父模块和依赖。所有模块属于同一分析会话，父关系与依赖分别校验无环。

`propose_analysis` 保存未批准的提案；`update_analysis` 仅在修订匹配时修改提案，保留旧版本事件。调用者确认后 `approve_analysis` 建立实际任务模块并冻结清单，尚不创建执行工作流。已确认的清单或材料变更时，创建带 previous_analysis_id 的新提案，保留原图和原工作流。

## 原生 3D 与分配

```sh
python -m agentgranule.design_view --database ABSOLUTE_DATABASE_PATH --analysis-id ACTUAL_ANALYSIS_ID --output-file ABSOLUTE_NEW_CHOICE_JSON_PATH
```

使用本地 Tk 原生窗口，全部模块置于**同一张 3D 图**，以带倒角和固定厚度的半透明薄片区域展示，采用维恩图式层叠布局。区域是实际三维薄棱柱，使用共享坐标系、相机和射线深度混色，不是球体。不启动网页或 HTTP 服务，也无需 OpenGL 插件。

拖动旋转整张图、滚轮缩放、点击片区或名称标签选中模块。点中重叠处时显示全部命中模块的选择菜单；左侧清单与图中编号对应，文字过密时可从清单查看完整名称。父关系与执行依赖另有虚线和箭头。片区重叠只是同图布局，不表示共享职责、集合交集或新依赖。模块名、当前方向、力度、来源及任务状态仍可查看。

按 `V(e)=Vmin+(Vmax−Vmin)×e` 映射体积；薄片固定厚度，因此平面面积与体积同样线性变化，平面尺寸按平方根变化。0.00 保留可见体积；未分配显示固定占位尺寸和“待分配”，不代表人工选择。多个方向按当前方向展示，不暗中合成“总力度”。栅格采样限制在 320×240 内，名称与边线由原生 Canvas 清晰绘制。

模块清单确认前可修改模块信息、方向、依赖与父关系。确认后在各模块／方向使用滑块或精确输入设置 0.00–1.00、步长 0.01 的力度。变化先在窗口本地预览；完整分配表供调用者检查，再明确确认保存。取消或关闭不会保存新力度；确认模块图与确认力度是两次不同的人工决定。

## 原子性与调度

`allocation_snapshot` 捕获图版本及全部方向的有效参数、来源和修订；`save_allocation` 要求每个模块／方向恰好一次，不接受缺项、重复、外部模块或非法小数。任何快照过期会拒绝整批保存，不部分覆盖。仅修改 design_effort，保留 detail_level、count、max_depth 及其他参数。

第一次完整力度确认后，设置、记录和工作流创建在同一事务中提交；任务按模块依赖展开到依赖模块的全部方向。后续改动使受影响任务与后继失效，无关结果保留。既有模块覆盖且力度相同的再次确认仅记录决定，不产生无意义修订；人工值即使等于项目默认也保存为模块覆盖，防止后续默认设置悄然改变分配。

所有值独立，不要求合计为 1。0.00 仍执行任务，不自动跳过、删除或批准占位结果。力度的语义由实际宿主处理，不承诺固定工时、令牌数或质量。

## Skill、CLI 与 MCP

同一组分析操作在 Python `Design`、JSON CLI 和 MCP stdio 暴露：analyze_framework、propose_analysis、update_analysis、get_analysis、approve_analysis、allocation_snapshot、save_allocation。MCP 总计 19 个工具；窗口由本地宿主启动，远程服务端不能代替调用者显示界面。

每次启动使用新的结果文件，等待真实用户操作。成功退出且 status=saved 才表示该份力度清单已确认；核对 analysis_id、workflow_id 与数据库实际状态后继续 next_task。cancelled、失败、运行中或缺少文件均不能视为人工批准。参数与图的修改、实际问答和结果经已有事件记录保存；只记录显式回传的可见对话，不读取其他聊天。

可以运行 `examples/design_framework.py` 生成本项目的真实分析提案并打开原生窗口；示例没有自动批准模块或填入人工力度。使用同一个数据库续作时，通过 --analysis-id 指定已有提案，避免反复创建会话。
