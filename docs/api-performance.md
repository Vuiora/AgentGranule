# 接口性能优化与验证

`codex/api-performance`基于维护者已合并PR #12的main `ffe339d216e1259020543cc762cedf813ab95378`。本轮改进模块API及MCP调用所共用的数据读取路径，降低原生窗口加载和保存所等待的接口成本。

模块／方向的粒度、模块信息和默认值在一次事务内分块联表读取，每块最多900个绑定参数，兼容999变量限制。每项参数独立JSON解码，保留排序、模块／默认值优先级与修订；不保留跨请求状态缓存，跨连接的新设置仍会使旧完整快照失效。

工作流状态或重复派发请求未变化时，不重写完整payload；发生失效或新派发时仍持久化。提交结果后的第二次依赖刷新复用同一写锁内读取的状态，重新计算依赖指纹，不改变`WORKFLOW_VERSION`或旧请求指纹的字节内容。

历史事件新增`events(session_id, sequence)`索引，使按会话读记录不扫描其他会话。首次打开旧数据库会创建索引，有一次性建索引成本；历史原文、序号、时间和schema user_version保持原有语义。没有省略记录或降低持久化设置。

## 前后性能对比

下表为同机合成夹具：500模块、每模块3方向，共1500任务，50,000条额外历史事件。每接口预热3次、测量15次，取中位数；前后所有输入、夹具及20个返回结果摘要相同。计数包含以`WITH`开头的只读查询。

| 接口 | 优化前 | 优化后 | 倍率 | SELECT次数前→后 |
| --- | ---: | ---: | ---: | ---: |
| 模块API：分配快照 | 54.05 ms | 13.25 ms | 4.08× | 4501→5 |
| 模块API：流程状态 | 33.99 ms | 11.80 ms | 2.88× | 3001→5 |
| 模块API：重复下一任务 | 27.25 ms | 11.78 ms | 2.31× | 3001→5 |
| MCP：分配快照 | 51.82 ms | 16.12 ms | 3.21× | 4501→5 |
| MCP：流程状态 | 56.53 ms | 29.77 ms | 1.90× | 3001→5 |
| MCP：重复下一任务 | 52.59 ms | 28.68 ms | 1.83× | 3001→5 |

稳定状态／重复下一任务的工作流UPDATE次数从每调用1次降为0。独立300对内存夹具的首次整批保存SELECT从3904降至1207，首次派发602→3，提交1201→2；逐控件保存及事件记录保留。

另测100模块。首次测量中MCP单项粒度与流程状态出现小幅耗时上涨，同配置复测未重现；亚毫秒及低毫秒结果受本机负载波动影响，不据此保证所有小接口都加速。

MCP基准使用真实`FastMCP.call_tool`，包含每调用数据库连接与响应转换，不包含stdio传输、模型执行或启动。工作流为模块依赖链，已有一个稳定派发请求，尚无接收结果；这些是该场景的接口读／轮询收益，不代表整个工作流或3D旋转帧率的收益。SQLite trace影响绝对耗时，生产延迟需在实际数据和负载下另测。

## 可复现基准与回归

```powershell
.venv\Scripts\python.exe benchmarks/api_performance.py --output .agentgranule/api-measurement.json
```

脚本仅创建临时数据库，合成模块图、模拟确认与事件记录，检查每次测量前后输入不变、返回结果稳定。原始结果提交于[基线](../benchmarks/api-performance-before.json)、[优化后](../benchmarks/api-performance-after.json)及[100模块复测](../benchmarks/api-performance-after-recheck-100.json)。优化后结果在工作区未提交代码时采集，其`git_head`为分支基线，待审查实现为本性能PR差异。

性能回归采用查询次数预算而非机器耗时阈值，覆盖551模块×3方向与1001任务跨分块读取、参数不共享引用、跨连接默认值／覆盖更新、完整快照拒绝与原子回滚、未变轮询不写入、失效／派发持久化、依赖指纹及事件顺序、旧库索引与原文排序。既有核心、CLI、MCP及原生图形回归仍须通过；测试不能代替人工批准。
